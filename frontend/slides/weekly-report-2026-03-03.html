Live BRAT Preview

See how edits look before saving — no more blind editing

ParagraphBratPreview

New

Live Update Mechanics

User ActionBRAT Response
Click entity type chipEntity colour changes instantly
Add/delete relationRelation arrow appears/disappears
Change relation typeArrow label updates (new in this fix)
Adjust span numbersEntity extent updates (300ms debounce)
Type user noteNo change (memoized, no spurious re-render)
How it works: Each change updates a previewKey string. When the key changes, React destroys and recreates BratEmbeddingDefault, which calls window.Util.embed() fresh with the modified entity data.

Features

  • Show All / Related Only toggle — filter to just the edited entity and its relation partners
  • Drag-to-resize handle (80px–600px) — expand for long paragraphs, shrink for compact view
  • Collapsible accordion — fully hide the preview when not needed
  • ResizeObserver — remounts BRAT when sidebar width changes, preventing blank previews
  • Memoized docData — prevents spurious embed() calls on unrelated parent re-renders
  • Full previewKey — captures relation type+target, not just count
  • No extra API calls — overrides paragraph data locally in memory

Settings-Driven Relations

Constraint-aware validation powered by settings.json

Constraint-Aware Relations

Fixed

Before (hard-coded)

  • 6 relation types hard-coded as <MenuItem> strings in Sidebar.tsx:1031–1038
  • No validation — user could create invalid Arg1/Arg2 type combinations
  • Out of sync with settings.json schema
  • Adding a new relation type required code change

After (settings-driven)

  • Reads settings.relation_types dynamically
  • Filters valid relation types per source entity type
  • Filters valid target entities per relation type
  • Schema change = config change only, no code edits

Helper Functions

FunctionRole
getRelationTypesForSource()Given a source entity type, returns only relation types whose Arg1 targets include that type
getValidTargetTypesForRelation()Given a relation type, returns valid Arg2 entity types
getContrastColor()Computes black/white text color from a hex background
toRelations()Safe cast from legacy array to typed Relation[]
Example: If the source entity is POLYMER, only has_property, has_value, abbreviation_of etc. appear in the relation dropdown. Target entities are filtered to only valid Arg2 types.

Optimistic Saves

New

Before

Every entity or relation save called navigate('/result'), triggering a full page reload. The PDF re-rendered, scroll position was lost, and the user had to find their entity again.

After

Saves are optimistic: local state updates instantly, the panel closes, and the API call runs in the background. On failure, changes revert and a snackbar notification appears.

Save Flow

1. User clicks Save
2. Local highlights[] updated immediately
3. Edit panel closes, entity list shows updated data
4. API calls fire in background (entity + relations)
5. Server response syncs bratOutput, updateId, etc.
6. On error: revert to originalHighlights + show snackbar

Responsive Layout & Overflow Fixes

BRAT Rendering Reliability

Preventing content disappearance during editing, resizing, and relation changes

BRAT Rendering Reliability Fixes

Fixed

Bug 1: Incomplete previewKey

Problem: previewKey only included currentRelations.length. Changing a relation’s type or target (without changing count) did not trigger BRAT remount.

Fix: previewKey now uses relations.map(r => type:arg_id).join(',') — any change to type or target produces a new key.

Bug 2: New docData reference on every render

Problem: docData was constructed inline (new object every render). BratEmbeddingDefault’s useEffect([docData]) compares by reference, so it fired window.Util.embed() on EVERY parent re-render (typing notes, toggling UI, saving). This caused BRAT to flicker or fail silently.

Fix: Wrapped all computation in useMemo keyed on previewKey + paragraphData. Reference only changes when actual content changes.

Other Rendering Fixes

Bugs Fixed

Fixed
Hard-coded relation types Fixed

6 relation <MenuItem> strings in Sidebar.tsx replaced with dynamic reads from settings.relation_types

BRAT preview disappearing on sidebar resize Fixed

Added ResizeObserver with debounced remount. Only triggers when width changes >10px (actual resize, not initial measurement).

Initial debouncedWidth change (0 → actual) was causing a spurious remount. Fixed by skipping the first width measurement in the key.

Sidebar overflow now toggles to hidden when EntityEditPanel is visible, preventing parent + child scroll conflict.

Sidebar max width too narrow for BRAT Fixed

Increased sidebar maximum resizable width from 500px to 700px.

Incomplete previewKey for relations Fixed

Key now includes full relation type+target (type:arg_id), not just currentRelations.length.

Spurious BRAT re-renders on unrelated state changes Fixed

Memoized docData with useMemo; reference only changes when actual BRAT content changes.
